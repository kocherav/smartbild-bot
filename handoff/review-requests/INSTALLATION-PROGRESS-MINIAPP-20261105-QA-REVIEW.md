# Заключение тестировщика: контроль прогресса монтажа и Telegram Mini App

Ответ на запрос `handoff/review-requests/INSTALLATION-PROGRESS-MINIAPP-20261105.md`
(ветка `review/installation-progress-miniapp-20261105`, коммит 98ac57c). Дата: 2026-11-05.

Статус: **модель поддержана по сути; MVP предлагается сократить примерно втрое**.
Решения владельца по четырём вопросам — в конце. Код не менялся.

## 1. Что уже есть в системе (сверено с кодом, а не со словами)

| Есть | Где | Значение для прогресса |
|---|---|---|
| Дата передачи в монтаж | `installations.transferred_at` | отсчёт «сколько дней прошло» |
| Работы: план, единица, **расценка монтажника** | `work_items.planned_qty`, `unit`, `rate` | готовый вес для каждой позиции |
| Отчёты с датой, заявлено / принято | `reports.report_date`, `report_items.declared_qty`, `accepted_qty` | фактическая кривая и темп бригады из истории |
| Защита от сверхплана при приёмке | `approve_report`: «объём превышает остаток» | готовность не может превысить 100% |
| Журнал действий | `audit_log` | история переносов без новой таблицы |
| Версии проекта | `project_versions` | изменение объёма уже версионируется |
| Mini App с проверкой входа через Telegram | `hogart-scraper/dashboard` (`verify_telegram`) | новый Mini App не нужен — вкладка в «Пульте сделок» |

**Нет:** плановых дат (начало/окончание), этапов, нормо-часов, нескольких бригад на объект
(`installer_name` — один), причин пауз, календаря рабочих дней.

## 2. Модель: что поддерживаю, что оспариваю

**Поддерживаю:** один источник истины поверх `installations/work_items/reports`; официален
только **принятый** объём; первоначальный срок не переписывается; задержка приёмки — не
отставание монтажника; готовность ≤ 100%; финансы отдельно от физической готовности.

**Оспариваю (для MVP):**
1. **10 состояний → 6.** «Требует планирования / График согласован / Готов к началу» и
   «Выполнен технически / Сдан / Закрыт» неразличимы для пользователя без отдельного процесса
   сдачи. MVP: `Передан, нет графика → Запланирован → В работе → Пауза (причина) →
   Ожидает приёмки → Завершён`.
2. **Неизменяемый baseline с версиями — не в MVP.** Достаточно: первоначальные даты (пишутся
   один раз) + текущие даты + запись в `audit_log` на каждый перенос с причиной и автором.
   Объём уже версионируется `project_versions`.
3. **Четыре показателя → два + план.** Показывать: план на сегодня, **принято** (официально),
   **заявлено, ждёт приёмки** (с возрастом ожидания). `technical_completion` — когда появится
   процесс испытаний и сдачи.
4. **Иерархия весов из пяти уровней — лишняя.** Нормо-часов нет, и формировать их до проверки
   ценности дорого. Предлагаю официальный вес **= расценка монтажника × плановое количество**:
   он есть у каждой работы, отражает трудоёмкость (за тяжёлую работу платят больше), монтажник
   не может его изменить. Равные веса не использовать никогда — они искажают картину.
5. **Гант — отложить** (согласен с запросом): этапов в данных нет.

## 3. Расчёт, устойчивый к манипуляциям

```text
Готовность (официальная) = Σ(расценка × min(принято, план)) / Σ(расценка × план)
Заявлено = то же по принятому + заявленному, ещё не принятому
План на дату = доля рабочих дней от планового начала до сегодня
Отставание, дн = (план на дату − готовность) × длительность в рабочих днях
Прогноз окончания = сегодня + остаток / темп принятых работ за последние 10 рабочих дней
```

- Знаменатель фиксируется при передаче в монтаж; изменение ведомости после старта меняет его
  только через новую версию с записью «было/стало», иначе процент «прыгает» задним числом.
- Темп — только по принятому и по `report_date`, а не по дате приёмки: иначе медленная приёмка
  выглядит медленной работой.
- Нет отчётов или меньше 3 принятых — прогноз «нет данных», не выдумываем дату.
- Пауза останавливает «план на дату», в истории остаётся с причиной и длительностью.

**Способы манипуляции и защита:**

| Риск | Защита |
|---|---|
| Монтажник завышает заявленное | официально только принятое; заявленное помечено «не принято» |
| Руководитель тянет с приёмкой | отдельный счётчик «ждёт приёмки N дней», не влияет на отставание монтажника |
| Перенос срока, чтобы скрыть отставание | первоначальная дата видна всегда; «перенесено N раз, на X дней», кто и почему |
| Правка расценок или плана в середине | знаменатель зафиксирован; изменение — версия с журналом |
| Отчёт задним числом | `report_date` не раньше передачи в монтаж и не позже сегодня; правка — новая ревизия |
| Дробление одного объёма на много отчётов | повторы уже не удваивают факт (сверхплан запрещён) |

## 4. Пропущенные роли, состояния и сценарии

- **Несколько монтажников / передача остатка другой бригаде** — схема поддерживает одного
  исполнителя. В MVP не делать, но поле назначения хранить на уровне работы, а не объекта,
  чтобы не переделывать модель.
- **Причина паузы «материалы»** — связать с закупкой (`procurement_workflow`): если позиции
  не доставлены, пауза предлагается автоматически, а не вручную.
- **Календарь** — производственный календарь РФ (праздники, переносы), часовой пояс МСК.
- **Объект без плановых дат** — состояние «нет графика» само по себе исключение в пульте.
- **Нет отчёта N рабочих дней при статусе «В работе»** — исключение (N = 3 по умолчанию).
- **Отмена принятого** — новая ревизия отчёта, прошлое в журнале.
- **Работа с нулевым планом / без расценки** — не участвует в весе, помечена.
- **Повторная передача той же сделки** — одна запись, не дубль (уже соблюдается `transfer`).

## 5. MVP для проверки ценности (2–3 недели вместо полного объёма)

1. При передаче в монтаж руководитель указывает **плановое начало и окончание** (кнопки «+5/+10
   рабочих дней» или дата), можно позже — тогда «нет графика».
2. Расчёт по разделу 3: готовность, заявлено, план, отставание, прогноз.
3. Состояния MVP (6) и **пауза с причиной** одной кнопкой у руководителя и монтажника.
4. **Пульт сделок → вкладка «Монтаж»**: список исключений с цветом и текстовой причиной
   (отстаёт, нет графика, нет отчётов, пауза, ждёт приёмки N дней, завершается на неделе);
   карточка объекта: первоначальный/текущий срок, план–принято–заявлено, график «план — факт»
   (накопительная кривая), очередь отчётов, журнал переносов.
5. **Монтажник остаётся в боте** (отчёты уже работают там); Mini App для него — после проверки
   ценности для руководителя. В «Мои монтажи» добавить строку «готово X% из плана Y%, срок …».
6. **Одна строка в утреннем списке** владельца: «Монтаж: отстают 2, ждут приёмки 3 (дольше всех
   — 4 дня), без графика 1». Отдельных уведомлений по каждому событию не слать.

**Не в MVP:** Гант, нормо-часы, несколько бригад, доступ клиента, `technical_completion`,
полноценные версии baseline.

## 6. Дополнения к матрице приёмки (к 20 пунктам запроса)

21. Готовность считается по расценке × количеству; правка расценки после старта не меняет
    прошлый процент без новой версии.
22. Темп и прогноз — по `report_date` принятых отчётов; задержка приёмки их не ухудшает.
23. Меньше 3 принятых отчётов — прогноз «нет данных».
24. Пауза останавливает план и видна в истории с длительностью.
25. Рабочие дни — по производственному календарю, МСК.
26. Отчёт с датой до передачи в монтаж или в будущем — отклоняется с понятной причиной.
27. Первоначальная дата не меняется ни одним действием; перенос пишет автора и причину.
28. Монтажник видит только свои объекты и не видит расценки других бригад.
29. Строка утреннего списка совпадает с вкладкой «Монтаж» (одно и то же число отстающих).
30. Пульт и бот показывают одну версию после фоновой синхронизации (метка «обновлено …»).

Для каждого пункта тестировщик добавит человеческий маршрут на стенде (бот + двойник CRM) до
выпуска; для пульта — проверку в браузере на 390 и 1400 px.

## 7. Ответы на вопросы владельцу — рекомендация тестировщика

1. **Официальный процент** — по стоимости работ монтажника (расценка × количество), только
   принятое. Нормо-часы — когда появятся.
2. **Нормативы** для MVP не нужны.
3. **Плановые даты** ставит руководитель при передаче в монтаж; переносит руководитель или
   владелец, всегда с причиной; первоначальная дата не меняется.
4. **Доступ клиента** — не в MVP; вернуться после месяца работы руководителя с вкладкой.

Внешнее согласование: **выполнено тестировщиком** со всеми замечаниями выше; окончательные
решения по разделу 7 — за владельцем.
