## 2. Причина — не одна кнопка, а класс ошибок

Номер сделки жил в ~20 полях состояния (`current_deal_id`, `installation_deal_id`,
`contract_deal_id`, `payer_target_deal_id`, `procurement_stock_deal_id`, …) и выставлялся
в 17 местах. Только `select_deal` (открытие из списка) чистил чужие поля; открытие сделки
фразой («покажи сделку 865»), ответом ассистента, поиском, созданием, договором по фразе
меняло `current_deal_id` и оставляло поля прежней сделки. Читатели предпочитали их
открытой карточке (`installation_deal_id or current_deal_id`, то же у остатков закупки,
договора). Кнопки под старыми сообщениями не помнили, для какой сделки нарисованы.
Ассистент получал дневной разговор с прошлыми сделками без указания открытой (06.11, №905 → №865).

## 3. Что переделано (правило «обсуждаем №N — действуем только с №N»)

Новый модуль `telegram-bridge/deal_context.py`, применяется в одной точке — в транзакции
записи состояния (`ui_context.StateStore.update`, `begin_idle`, файловый путь):

1. **Смена открытой сделки стирает всё, что относилось к прежней**, в той же транзакции:
   предпросмотры договора/счёта/КП/экономики, привязанные ID, выбранного подписанта,
   ожидающий шаг сделки, цель загрузки файла. Оставляются только продолжения, которые
   называют свою сделку на кнопке (КП, смена плательщика), и работа не по сделке
   (банк, счета поставщиков, создание новой сделки, кабинет монтажника).
2. **Открытая карточка всегда важнее привязанного ID** (монтаж, остатки, договор); если
   шаг договора относится к другой сделке — ничего не формируется, бот говорит об этом.
3. **Загрузка проекта**: цель фиксируется при нажатии «📤 Загрузить новый файл», бот называет
   сделку; при получении файла цель обязана совпасть с открытой сделкой, иначе файл не
   прикрепляется (fail-closed) с понятным сообщением. Ответ о записи называет сделку.
4. **Кнопки помнят свою сделку**: каждый экран в `workflow_runtime.views` хранит `deal_id`.
   Кнопка действия сделки A при открытой B не выполняется («Кнопка относилась к сделке №A,
   а сейчас открыта №B. Ничего не выполнено»). Навигация и открытие сделок не блокируются.
   То же для набранного «да».
5. **Названная в сообщении сделка становится открытой** (оплата, счёт, статус, плательщик,
   исполнитель, экономика): следующий вопрос без номера — о ней.
6. **Номер сделки под предпросмотром** открывает эту сделку (раньше — «Уточните…»),
   предпросмотр прежней сделки сбрасывается.
7. **Ассистент** в каждом ходе получает строку «сейчас открыта сделка №N … номера из прошлых
   сообщений не используй» (или «сделка не открыта — спроси номер»).
