# TASK-20261125-03 — сделка 907, цена есть, «План материалов» был 0

## Итог

Точная причина — окно eventual consistency Megaplan между записью `POST /offer/{id}` и чтением вложенного Offer через `GET /deal/907`. Команда записала закупку в правильные Offer, но немедленное чтение сделки/экономики получило старую вложенную копию Offer с нулём. Это не ошибка сопоставления `offer_id` и не потеря записи: на контрольном чтении 25.11 поле закупки уже заполнено в RUB как в `GET /offer/{id}`, так и в `GET /deal/907 positions[].offer`.

`build_profitability_report.py` строит «План материалов» непосредственно из свежего `GET /deal/{id}` → `ledger_from_deal`; локальный `deal_ledger` используется там только для признака basis. Маршрут `fetch_deal_ledger(force=True)` → `sync-deal-ledger` также берёт те же вложенные `positions[].offer` и потому в период рассогласования сохраняет те же нули. Локальный `ledger/907.json` с mtime `2026-11-25 19:07:02 UTC` действительно содержит 0 у этих строк. Строки из TASK-20261124-13 были записаны раньше и к моменту чтения уже успели сойтись, поэтому у них план был виден.
