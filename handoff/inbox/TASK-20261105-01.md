Решения владельца: официальный процент — по стоимости работ монтажника (расценка × количество),
только принятое; нормы трудозатрат не нужны; сроки ставит руководитель при передаче в монтаж,
переносит руководитель или владелец, всегда с причиной, первоначальная дата не меняется; доступа
клиента нет; монтажник денег не видит (только проценты и объёмы).

Инструкцию для монтажника пишет тестировщик (`telegram-bridge/docs/INSTALLER_GUIDE.md` и
картинки рядом). Ты её НЕ пишешь — только подключаешь (п. 6).

## Что сделать

### 1. Данные (`megaplan-crm/installation_workflow.py`, миграции без потери данных)
- В `installations`: `planned_start`, `planned_finish` (текущие), `original_start`,
  `original_finish` (пишутся один раз и больше никогда не меняются), `plan_value` — Σ(rate ×
  planned_qty) на момент передачи в монтаж (знаменатель процента).
- Таблица пауз: начало, конец, причина из списка (клиент, проект, материалы, доступ,
  электропитание, решение руководителя, другое) + комментарий, автор.
- Перенос срока — запись в `audit_log` (было/стало, причина, автор); первоначальные даты не трогать.
- Изменение ведомости после старта меняет `plan_value` только через новую версию с записью
  «было/стало» (как `project_versions`).

### 2. Расчёт (одна функция, используют бот, пульт и утренний список)
Формулы — раздел 3 заключения: готовность (принято), заявлено, план на дату по рабочим дням
производственного календаря РФ (МСК), отставание в рабочих днях, прогноз по темпу ПРИНЯТЫХ
работ за 10 рабочих дней по `report_date`; < 3 принятых отчётов — «нет данных»; диапазон прогноза;
пауза останавливает план; задержка приёмки — отдельный счётчик «ждёт приёмки N дней», в отставание
монтажника не входит; готовность ≤ 100%; работы с нулевым планом или без расценки в вес не входят.
Состояния — 6 из раздела 2 заключения.

### 3. Бот
- При «✅ Перевести сделку в Монтаж» руководитель указывает сроки (кнопки «+10 / +20 / +30 рабочих
  дней», ввод даты или «позже» → состояние «нет графика»).
- Руководителю в карточке монтажа: «⏸ Пауза с причиной», «▶️ Снять паузу», «📅 Перенести срок»
  (с причиной).
- Монтажнику в «🛠 Мои монтажи» у каждого объекта строка «готово X% · по плану Y% · срок …»;
  кнопки «📊 Мой прогресс» (открывает урезанный пульт, п. 5) и «🚧 Сообщить о препятствии»
  (уведомляет руководителя; паузу ставит руководитель).
- Утренний список владельца: одна строка «Монтаж: отстают N, ждут приёмки M (дольше всех — K дн.),
  без графика L» — те же числа, что во вкладке «Монтаж».

### 4. Пульт сделок → вкладка «Монтаж» (руководитель), эскизы 1–2
Список исключений со сводкой и фильтрами; карточка объекта: 4 показателя, сроки (первоначальный,
текущий, переносы, паузы), накопительный график «план — заявлено — принято» с «сегодня» и прогнозом,
«почему отстаёт» текстом, прогресс по работам, очередь приёмки (Принять / Частично / Отклонить —
через существующую приёмку, без второго реестра), пауза, перенос, журнал. Метка «обновлено …».

### 5. Урезанный пульт монтажника, эскизы 3–4
Тот же Mini App (проверка Telegram `initData`, как в пульте), роль «монтажник» по привязанному
аккаунту: только его объекты, без денег, без чужих расценок, без кнопок руководителя. Экран
объекта: готово/отправлено/по плану, подсказка о нужном темпе, график, статусы его отчётов с
причинами частичной приёмки, остатки по работам, «Отметить выполненное» (ведёт в существующий
отчёт в боте), «Сообщить о препятствии». Монтажник не меняет сроки и состав работ.

### 6. Инструкция (только подключение)
В меню монтажника кнопка «📘 Инструкция»: бот показывает оглавление разделов из
`telegram-bridge/docs/INSTALLER_GUIDE.md` (заголовки `##`) кнопками; раздел присылается текстом,
картинки раздела (ссылки `![...](...)` на файлы рядом) — фото с подписью. Без ИИ, без записи в CRM.
Если файла нет — «Инструкция готовится». В пульте монтажника — ссылка «Инструкция» на то же.

### 7. Проверки (обязательно, до отчёта)
- Человеческие маршруты на стенде (`HumanJourneyCase`, двойник CRM) на пункты 1–30 матрицы
  приёмки (раздел 6 заключения + запрос), минимум: передача со сроками и «позже»; частичная
  приёмка меняет готовность ровно на принятое; повтор отчёта не удваивает; пауза и снятие паузы;
  перенос не меняет первоначальный срок; изменение ведомости — версия; монтажник видит только свои
  объекты и не видит денег; утренняя строка совпадает с вкладкой; «нет данных» при < 3 отчётов.
