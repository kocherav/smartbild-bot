Решение владельца 05.11 — обязательное дополнение к TASK-20261105-01 (прогресс монтажа). Если

## Правило доступа монтажника

Разрешено: его объекты (адрес, контакт, проект), монтажная ведомость (работы, единицы, плановые
количества, ЕГО расценки и плановая сумма ему), его отчёты и их приёмка, прогресс монтажа в
процентах и объёмах, его взаиморасчёты (начисления, выплаты, зачёт), материалы по счетам БЕЗ цен.

Запрещено: экономика и рентабельность сделки, сумма сделки, продажные цены материалов и работ
клиенту, закупочные цены и поставщики материалов, счета клиенту, платежи клиента, данные других
монтажников, любые сделки, не переданные ему.

## Что сделать
1. В урезанном пульте монтажника (TASK-20261105-01, п. 5) ответы API для роли «монтажник»
   собираются по белому списку полей, а не скрытием в интерфейсе: в JSON для монтажника денежных
   полей сделки и полей материалов с ценами нет вовсе. Процент готовности — без сумм.
2. Аудит существующих входов монтажника и тесты на каждый:
   - «Текущее выполнение по сделке …» (`handle_current_execution_ui`) обрабатывается ДО проверки
     роли — монтажник должен получать ведомость только по своим объектам, без продажных цен;
   - команды `/экономика`, `/счет`, `/сделка` и фразы «экономика/прибыль/счёт по сделке N» от
     монтажника не выдают данных (сейчас уходят в кабинет — закрепить тестом);
   - «📋 Монтажная ведомость», «📦 Материалы по счетам», «📊 Мои взаиморасчёты», «📚 Утверждённые
     отчёты», «📜 История монтажей», сборный отчёт — проверить содержимое файлов (xlsx/pdf) на
     отсутствие продажных и закупочных цен и чужих сделок;
   - пульт сделок (`hogart-scraper/dashboard`): для монтажника — только его вкладка, остальные
     API пульта отвечают 403.
3. Человеческие маршруты на стенде от лица монтажника: попытки получить экономику, счёт, чужую
   сделку, чужую ведомость — отказ без данных; разрешённое — работает. Тест ответа API пульта
   для роли «монтажник» на отсутствие запрещённых полей.
4. `quality_gate.py --run` — 0 ошибок. Записей в живую CRM нет.
