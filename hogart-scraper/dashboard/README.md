# Пульт сделок SmartBild

Рабочий адрес: https://claude.smartbild.su/deal-dashboard/

Вход — постоянная кнопка меню «Пульт сделок» в личном чате владельца с действующим Telegram-ботом. Сервер проверяет подпись Telegram Mini App и ID владельца из существующей конфигурации бота. Для обычного браузера предусмотрен одноразовый код: внутри Mini App выбрать «Вход на компьютере», затем ввести код на странице входа. Код действует 5 минут, сессия — 12 часов. Ссылка сама по себе не открывает финансовые данные.

## Возможности

- Сводные суммы, график платежей за 8/12 недель, кольцевая диаграмма оплаты, подтверждённая готовность закупок, распределение по этапам.
- Фильтры по состоянию, году создания, ответственному, компании, тексту, этапу, сигналу и неделе платежа. По умолчанию — активные продажи **всех лет**. В CRM остаются старые активные сделки; фильтр года явно означает год создания, а не год оплаты.
- Полоса над фильтрами показывает размер текущей выборки. Кнопки «Все за 2026 год» и «В работе за 2026 год» сбрасывают поиск, компанию, ответственного и фильтры диаграмм. Все ограничения видны отдельными метками. В списке указано число показанных карточек и доступна кнопка «Показать все».
- Карточка сделки: клиентские счета, денежные операции, учтённые счета поставщиков, позиции закупки и источники данных. Переход в Мегаплан.
- Чеклисты с ответственным, сроком, комментарием и отметкой выполнения. Собственная SQLite, журнал изменений, защита от одновременного перезаписывания. Чеклисты не меняют CRM. Типовой шаблон добавляется только по нажатию пользователя.
- Адаптивная мобильная версия, поиск и пустые состояния. Открытая страница получает свежий снимок раз в минуту, кроме открытой карточки с редактированием.

## Объекты и действия · первый этап расширения

- «Объекты»: карточки всех сделок текущей выборки; пока связи не подтверждены, каждая сделка остаётся отдельной карточкой. Вкладка «Связи» позволяет задать название, адрес и выбрать связанные продажи из всех лет. Совпадение клиента или адреса само по себе не объединяет сделки. Одна сделка входит только в один объект; снятая связь возвращает её в отдельную карточку. Карточка явно показывает, сколько её сделок попало в фильтры; её суммы всегда охватывают все связанные сделки.
- «Монтаж»: чтение существующего `installations.sqlite3` в режиме `mode=ro` и `query_only`. Ведомости, принятые количества по позициям, статусы отчётов и перечень проектных документов. Количества берутся только из `approved` / `partially_approved`; разные единицы не складываются. Согласование отчётов остаётся в существующем боте. Отсутствие или сбой источника явно отделены от отсутствия ведомости.
- «Сроки»: поступление клиента, выплата поставщику или поставка, привязанные к конкретной сделке. Дата бывает предварительной или согласованной; для согласованной обязательно основание. Суммы денежных сроков — целые копейки. Закрытие вручную и отмена исключают срок из очереди, но не создают платёж или приёмку. Автоматического сопоставления с фактами на этом этапе нет.
- «Действия»: очередь по текущим фильтрам — прошедшие сроки, ближайшие 7 дней, позже и без даты. Введённые планы показаны графиком на шесть недель. Это календарь внесённых планов, не полный прогноз денежных остатков и не расчёт долга.
- Зависимости чеклистов: задача может ждать другую задачу того же объекта. Сервер запрещает циклы, преждевременное завершение и возврат предшественника в работу при выполненных зависимых задачах. Разделение объекта с межсделочными зависимостями требует сначала изменить зависимости.
- История: последние 100 локальных изменений объекта, сроков и задач с автором, временем и подробностями. Изменения CRM сюда не входят. Сохранённые виды включают раздел, фильтры и сортировку, хранятся на сервере и доступны на другом устройстве владельца; лимит 30 видов.

В рабочую базу не заносятся демонстрационные объекты, планы или задачи. Группировка на трёх пилотных объектах и редактирование проверяются в отдельной тестовой SQLite.

## Семантика

Деньги считаются целыми копейками. Операции объединяются по CRM ID, поэтому связь одновременно со счётом, сделкой и банковским реестром не увеличивает сумму. Для продажи денежная сторона — `incomeSum` при `kind=income`, для закупки — `expenseSum` при `kind=expense`. Вторую, товарную сторону не суммируем. Возвраты учитываем с обратным знаком в рамках типов продажи/закупки. Неоднозначные связи одной операции с несколькими сделками исключаются до распределения. При неполном списке или неизвестной валюте остаток не вычисляется.

«Осталось получить» — разница рублёвой стоимости сделки и учтённых поступлений, а не просроченная задолженность. Переплаты показаны отдельно. Полнота списка операций в API не означает полноту исторического разнесения фактических банковских платежей. Закупочная схема «Покупка товаров» исключена из сводки продаж.

Основной график показывает фактические платежи. График в разделе «Действия» отдельно показывает введённые пользователем сроки. Прошедший срок требует проверки актуальности и факта; он не объявляется финансовой просрочкой автоматически.

Реестр закупок покрывает только часть сделок и потребности. `actual_qty` означает привязку счёта к позиции; это не приёмка. Заказ подтверждается журналом принятого заказа поставщика, включая явно подтверждённые дополнительные заказы. Строка «заказано через API» из старого реестра сама по себе доказательством не считается. Приёмка — только `received_qty`. Проценты — средняя подтверждённая доля количества каждой позиции, без сложения штук, метров и рублей. Неподтверждённая часть не объявляется физически незакупленной. Оплата общего счёта не распределяется между сделками пропорционально без подтверждённых связей.

## Файлы и службы

- `sync.py` — полная постраничная загрузка сделок, счетов и схем через существующий клиент и общий ограничитель запросов Мегаплана. Только GET, кроме существующего механизма авторизации клиента. Публикует снимок атомарно после успешной полной загрузки. Не изменяет статусы и финансы CRM.
- `model.py` — проверяемые расчёты и ограниченная проекция исходных данных для интерфейса.
- `workspace.py` — подтверждённые связи объектов, планы, история, сохранённые виды и чтение монтажного реестра.
- `server.py` — API, статический интерфейс, авторизация и чеклисты. Слушает только `127.0.0.1:8096`.
- `static/` — HTML/CSS/JavaScript и SVG-графики без сборщика и сторонних библиотек графиков.
- `data/crm.json` — последний полный снимок; `sync-status.json` — результат последней попытки.
- `data/dashboard.sqlite3` — сессии, одноразовые коды, чеклисты, журнал изменений. Не удалять при обновлении.
- `deploy/` — постоянные systemd units и точечное управление маршрутом Caddy.

Службы установлены ссылками на файлы `deploy` через `systemctl link`:

```bash
sudo systemctl status deal-dashboard.service
sudo systemctl status deal-dashboard-sync.service
sudo systemctl list-timers 'deal-dashboard-*'
sudo systemctl restart deal-dashboard.service
sudo systemctl start deal-dashboard-sync.service
```

Синхронизация стартует каждые 10 минут и использует фоновый бюджет существующей интеграции. Во время сбоя остаётся последний успешный снимок с отметкой об устаревании. Дата выписок показана отдельно от даты CRM. Финансовые реестры читаются из исходного каталога, поэтому их атомарные обновления видны приложению.

Маршрут `/deal-dashboard` и `/deal-dashboard/*` обслуживается Caddy на существующем домене. `/etc` в рабочем окружении доступен только для чтения, поэтому маршрут добавлен через официальный локальный API Caddy с ETag, без замены остальных маршрутов. `deal-dashboard-route.timer` проверяет его раз в 30 секунд и восстанавливает после перезагрузки Caddy. Он не изменяет существующий маршрут с совпадающим ID, если тот отличается от ожидаемого. Для отключения сначала остановить timer, затем удалить только `/id/smartbild-deal-dashboard` через Caddy API. Фрагмент `deploy/caddy-route.txt` оставлен для возможного переноса в основной Caddyfile.

Проверка Telegram соответствует [официальной документации Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Работа с маршрутом — [API Caddy](https://caddyserver.com/docs/api). Ключи и токены не передаются в интерфейс; сессионный токен хранится только в sessionStorage вкладки. API требует авторизацию, изменения дополнительно проверяют Origin. Сервер ограничивает размер запросов, число потоков и частоту попыток входа.

## Проверки

```bash
python3 -m unittest discover -s dashboard/tests -v
bash dashboard/tests/run-browser.sh
```

Браузерная проверка использует отдельную временную SQLite на порту 8097. Проверяет вход, отказ постороннему пользователю, Origin, недоступность данных без входа, фильтры, карточки, создание/изменение/сохранение чеклиста, экранирование HTML, одноразовость кода, мобильную ширину и выход. На рабочей базе тестовые задачи не создаются. Скриншоты и результаты проверки размещены в `evidence/`, этот каталог не раздаётся веб-сервером.


### Обновление и резервная копия

Схема SQLite версии 2 добавляется без удаления прежних данных: `objects`, `object_deals`, `plans`, `workspace_audit`, `saved_views` и поле `tasks.depends_on`. Миграция повторяемая. Изменения объектов, сроков и задач защищены проверкой версии и транзакцией. Соединения закрываются после каждого запроса.

Перед выпуском остановить `deal-dashboard.service`, сохранить код и согласованную копию SQLite через `Connection.backup`, проверить `PRAGMA integrity_check` и миграцию на копии. После замены файлов запустить службу и проверить авторизованный API и интерфейс. Для отката остановить службу и восстановить **код вместе с копией базы**: старый обработчик вставки задач не совместим с добавленным столбцом. Не восстанавливать базу поверх работающего сервера. Снимок `crm.json` и другие внешние реестры откатывать не требуется.

Браузерный запуск теперь включает `workspace-browser.cjs`: три тестовых объекта, уникальность связей, конфликты версий, неизменность денежных данных CRM, ввод сроков, отмену, зависимости, историю, сохранённые виды и мобильные формы. Для проверки подготовленного каталога можно задать `DASHBOARD_SOURCE=/path/to/staging`. Тесты не пишут в рабочую базу, Мегаплан или монтажный реестр.


### Постоянный вход из бота

В главном меню и разделе «Работа со сделками» добавлена текстовая кнопка «📊 Пульт сделок»: она возвращает повторно используемую inline-кнопку Web App. Команда `/dashboard` делает то же самое. В ответе раздела сделок также есть прямая inline-кнопка. Запуск не использует одноразовый workflow callback и не сбрасывает текущий черновик. Меню Mini App владельца восстанавливается при запуске моста. Нижняя клавиатура намеренно не запускает Web App напрямую: такой способ не передаёт необходимые авторизационные данные ([Telegram](https://core.telegram.org/bots/webapps#webappinitdata)).

При повторном открытии страница сначала проверяет сохранённую серверную сессию. Только при её отсутствии или отказе использует свежий Telegram initData. Просроченные данные без действующей сессии по-прежнему отвергаются. Регрессия: `tests/reopen-browser.cjs`.
