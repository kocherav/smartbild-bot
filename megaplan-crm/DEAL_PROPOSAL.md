# КП из существующей сделки

Кнопка руководителя: «📄 КП по сделке». Текст: «Сделай КП по сделке №896».
Бланк: `sites/cliwell/pack/04-print/blank-a4-2026-letterhead.pdf` (2026).

Форма с 29.09.2026 — по образцу КП на перенос компрессора, приложенному владельцем.
Первый лист: персональное обращение, суть предложения, основные позиции,
голубой блок итогов и подпись генерального директора Кочержинской С.В.
Со второго листа — полная спецификация. Скрытые тексты старого макета и условия
конкретного компрессорного проекта не копируются.

Перед каждой генерацией обязателен адресат: имя/ФИО или готовое обращение.
Ответ привязывается к ID задачи, а не к последней выбранной сделке. Клиент CRM
не меняется. Для имени используется нейтральное «Добрый день, ...!»; готовое
обращение сохраняется. Адресат входит в хеш версии PDF.
Переход стадии запускает запрос адресата. Активный сторонний диалог сохраняется:
вместо перезаписи его состояния отправляется кнопка с ID сделки.

`deal_proposal.py` читает живую сделку, переносит все позиции, количество,
единицы и конечные суммы строк `OfferRow.sum`, проверяет их сумму против
`Deal.price`. Цена за единицу выводится с достаточной точностью, без повторного
применения скидки. Валютные/неполные/несогласованные суммы блокируют генерацию.
Клиентский PDF содержит только белый список коммерческих полей. Закупочные
цены, прибыль, служебные JSON и информация о скидке в PDF не передаются.

Автоматика: стадия 131 программы 16 («Коммерческое предложение»), проверена
по живым переходам API. Переход из бота ставит задание сразу. Изменения в самом
Мегаплане обнаруживаются через общий кеш сделок (TTL 300 секунд) и минутную
фоновую проверку: обычная задержка до 5–6 минут плюс время генерации/доставки.
При первом включении текущие стадии запоминаются без массовой генерации старых КП.
Короткий выход/возврат на стадию между двумя опросами может не обнаружиться;
для такого случая доступна ручная кнопка. Мгновенный внешний запуск требует webhook.

Хранилище: `deal_proposals/<id>/` — версии PDF и публичные снимки.
`published.json` — актуальное вложение и комментарий. Общая очередь переходов
`transitions.json` сохраняется на диск. Автоматическое задание снимается после
успешной отправки вопроса об адресате в Telegram. PDF формируется после ответа.
Ошибки опроса повторяются; первое предупреждение приходит
руководителю. Таймаут Telegram после фактической доставки может привести к повторной
отправке файла: exactly-once между внешними сервисами не гарантируется.

Одинаковый снимок/дата/версия бланка повторно не загружается. При изменении данных
обновляется вложение в служебном комментарии, локально старый PDF сохраняется.
Если редактирование прежнего комментария запрещено (403) или он удалён (404),
новый PDF публикуется отдельным комментарием; прежний файл не удаляется.
ID загруженного файла сохраняется до привязки, чтобы повтор не загружал его заново.
Успех подтверждается через `/deal/<id>/allFiles`, в том числе при повторном получении.
Блокировка на сделку исключает параллельную генерацию двух одинаковых вложений.
Перед загрузкой повторно проверяются данные сделки на конкурентное изменение.
Общие обработчики КП больше не создают сделку без явного запроса на создание.

Проверка: `.report-venv/bin/python3 -m unittest discover -s megaplan-crm -p test_deal_proposal.py`.
Тесты не меняют CRM; отдельно выполнена реальная генерация для сделки 896.
Переходы стадий тестируются на подставных ответах, рабочие стадии ради теста не меняются.
