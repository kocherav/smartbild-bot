## Правила ведения

1. Перед работой прочитать план, карточку сценария и относящиеся к ней решения. Проверить фактическое состояние кода.
2. Для каждого изменения указать ID этапа и сценария, ожидаемый результат и проверку. Не переходить к следующему этапу без выполнения критерия выхода; препятствия записывать.
3. Разделять: пожелание, принятое бизнес-правило, найденное в коде, проверенное тестом, проверенное в рабочей среде. Не подменять одно другим.
4. Решения записывать с датой, основанием, статусом и последствиями. Отменённые решения сохранять со ссылкой на замену.
5. После действия записывать изменённые файлы, команды проверок, фактический результат, ограничения и способ отката. Секреты, токены, реквизиты и содержимое клиентских документов не копировать.
6. «Выполнено» означает достижение конечного критерия задачи с доказательствами каждого обязательного этапа по QA-2026-10-14. Перечень ограничений не превращает невыполненный этап в выполненный. «Тест пройден» не означает, что проверен Telegram или Мегаплан.
7. Новые пожелания сначала добавлять в очередь. Срочное отклонение от плана фиксировать отдельно с причиной и влиянием на этапы.
8. Планирование не разрешает создавать заказы, расходы, менять сделки или отправлять документы внешним получателям. Для боевых проверок заранее определить точный объект, действие и соответствующее разрешение.
9. При конфликте документов не угадывать. Зафиксировать расхождение, учесть последнее явное решение пользователя, уточнить неясное и только затем менять код/данные.
