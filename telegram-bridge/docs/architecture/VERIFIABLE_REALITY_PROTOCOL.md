# Обязательный протокол проверяемой реальности

Статус: обязателен для каждой серьёзной задачи SmartBild.

## Правила

1. Работать только от проверяемой реальности.
2. До реализации сначала показать фактическую архитектуру, реальные данные и маршрут пользователя.
3. Не придумывать сущности, статусы, ответы, результаты и возможности системы.
4. Синтетические тесты разрешены только для технической механики и всегда помечаются словом «СИНТЕТИЧЕСКИЙ». Они не подтверждают работоспособность бизнеса.
5. Проверка пользовательского сценария засчитывается только при наличии полного протокола: реальный ввод → ответ бота → внутреннее действие → внешний результат → повторное чтение результата.
6. Если реальную проверку выполнить нельзя, писать «НЕ ПРОВЕРЕНО», указывать конкретную причину и не заменять её имитацией.
7. Не называть задачу выполненной по количеству unit-тестов. Отдельно указывать статусы: «реализовано», «проверено изолированно», «проверено на реальных данных», «подтверждено в работающей системе».
8. До любых хозяйственных записей показать план, объект проверки, ожидаемые изменения и способ отката. Без подтверждения разрешено только чтение.
9. Найденный дефект передавать разработчику только с доказательствами воспроизведения. Неподтверждённые предположения помечать как гипотезы.
10. После исправления повторить тот же пользовательский маршрут целиком. Технический тест не заменяет повторную приёмку.
11. При противоречии между удобством тестирования и реальностью выбирать реальность.
12. При нехватке данных остановиться и задать один конкретный вопрос.

## Карточка перед началом работы

Перед началом каждой серьёзной работы отправить владельцу короткую карточку:

- Что проверяем.
- На каких реальных данных.
- Что разрешено изменять.
- Какой конечный бизнес-результат.
- Какие доказательства будут представлены.
- Что останется непроверенным.

Карточка должна быть отправлена до реализации и до любых хозяйственных записей.

## Главное правило

Лучше честное «НЕ ПРОВЕРЕНО», чем убедительный выдуманный результат.
