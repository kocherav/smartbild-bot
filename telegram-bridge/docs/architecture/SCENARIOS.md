## QA-AGENT — автономный тестировщик и постановка разработчику (2026-10-20)

Результат: сопровождающий запускает единый агент, который получает проверяемую
квитанцию полного или браузерного прогона, не принимает skip/нарушение изоляции
за успех, объединяет повторный инцидент и выдаёт агенту-разработчику постановку
с точной границей сбоя и обязательным протоколом QA-2026-10-14.

Входы: CLI `run` для штатных профилей, `inspect` для готовой квитанции, `dispatch`
для явной передачи внешнему developer worker. Роль — технический сопровождающий;
Telegram/CRM/email/архив/финансовые реестры не изменяются. Источник истины —
исходная квитанция тестового раннера; `qa-agent-state.json` хранит только историю
прогонов, fingerprint и состояние передачи. Повтор одинакового сбоя увеличивает
occurrences, но не создаёт вторую активную задачу.

| Шаг и вход | Исполнитель / запуск | Состояние и выход | Проверка результата | Отказ / рабочее продолжение |
|---|---|---|---|---|
| `run full/browser` | QA-агент, вручную или планировщиком | изолированная квитанция и execution log | return code плюс содержимое receipt | нет квитанции → отдельный failed defect |
| анализ квитанции | детерминированный triage | run и ready task либо зелёный run | skip, blocked event и unsuccessful не зелёные | повреждённый JSON останавливает обработку |
| повтор дефекта | registry fingerprint | та же задача, occurrences+1 | стабильный набор test IDs/status | новый набор падений → новая задача |
| `dispatch` | внешний developer worker | stdout/stderr, awaiting_verification | разработчик получил полный prompt через stdin | ненулевой код → ready для ограниченного повтора |
| повторная приёмка | QA-агент | новая квитанция на новой версии | исходный профиль и затем release gate | успех разработчика сам задачу не закрывает |

Инварианты денег/количества/единиц применяются к тестируемым сценариям, но агент
сам их не изменяет. Дедупликация, атомарная запись и fail-closed разбор проверены.
Реализован human-профиль и первый полный маршрут HUMAN-DEAL-STATUS через polling,
состояние диалога, реальную inline-кнопку, фоновый worker и CRM-boundary с обратным
чтением результата. Остальные восемь обязательных маршрутов намеренно имеют P1
`missing`; агент больше не может объявить систему проверенной по числу unit-тестов.
Human-расписание как отдельный timer пока не установлено. Автоматический claim/lease
после решения владельца и живая интеграция карточек в общий polling реализованы.

QA-HANDOFF дополнение: `qa_handoff.py` связывает QA-реестр с существующим Codex
developer worker. Владелец видит короткую Telegram-карточку и принимает одно из
двух одноразовых решений. До `approved` claim невозможен; после claim повторный
запуск невозможен. Успех разработчика означает `awaiting_verification`, а не
закрытие. Вопрос владельцу допустим только для бизнес-неоднозначности через общий
decision_channel. Технический сбой, тест и исправление не перекладываются на владельца.

## QA-38832571B75E75245541 — browser runtime (2026-10-21)

- Результат: browser-профиль запускает 12 сценариев только при наличии совместимого Chromium; отсутствие исполняемого браузера фиксируется как внешняя инфраструктурная блокировка, а не дефект пульта и не задача изменения бизнес-кода.
- Воспроизведение: все сценарии остановились до открытия страницы с `Executable doesn't exist ... chromium_headless_shell-1234`; затем runner получил `PermissionError` при записи общего evidence-файла. Функциональный маршрут пульта не исполнялся.
- Реализовано: QA распознаёт сигнатуру отсутствующего Playwright runtime как `infra:playwright-browser`; `infra:*` исключён из автоматической передачи разработчику. Для runner предусмотрен отдельный evidence-путь текущего QA-запуска.
- Ограничение: сам runner пока нельзя исправить — `hogart-scraper/dashboard/tests` принадлежит `nobody`, текущий uid не имеет записи. В нём также остаются порты 8097/8098, которые требуется заменить на разрешённые 48097/48098. Обход ACL и установка браузера не выполнялись.
- Продолжение: владельцу отправлен `Q-BROWSER-QA-RUNTIME`, Telegram 3707, с просьбой через SSH установить Chromium текущей версии Playwright и восстановить запись `smartbild-projects` в каталог тестов. После этого обязательны изменение runner, повтор всех 12 сценариев и проверка evidence.
- Проверено изолированно: QA 15/15, autopilot/handoff 25/25, полный gate 1088/1088. Browser acceptance — `НЕ ПРОВЕРЕНО`; хозяйственные данные не менялись.
- Повтор `20261021T223130Z-browser-3cb1ca93` выявил вторую границу: receipt уже содержал `infra:playwright-browser / blocked`, но `report_failures` игнорировал blocked cases и подменял их `runner:incomplete`. Теперь `blocked` сохраняется как самостоятельный failure с исходным ID; автопилот видит `infra:*` и переводит задачу в ожидание внешнего runtime. Регрессия покрывает receipt→registry и соседние failed/error/skipped/missing/isolation статусы.
