# ТЗ: отчёты монтажников, фактическая себестоимость и взаиморасчёты

## 1. Зафиксированные правила

- Один Telegram-пользователь монтажника соответствует одной бригаде и одному исполнителю Мегаплана.
- Отчёт может прислать монтажник или руководитель.
- Один отчёт может содержать работы по нескольким сделкам и объектам.
- Монтажник видит весь плановый объём работ по привязанной к нему сделке, но не видит выручку, маржу, закупочную стоимость оборудования и общую экономику организации.
- Руководитель видит план, факт, отклонения, все начисления, удержания и выплаты.
- Распознанный отчёт сначала создаёт черновик. Запись в утверждённый факт и сумму к оплате выполняется только после подтверждения руководителя.

## 2. Что показали четыре исходных отчёта

Встречаются следующие формы строк:

1. Объём × ставка = сумма: `63×440=27 720`, `3×5 500=16 500`.
2. Объём и общая сумма без ставки: `труба 3/8 25 м + флекс — 7 800`.
3. Только общая сумма: `монтаж приточки — 15 000`.
4. Агрегат по внешней таблице: `по таблице — 108 500`.
5. Неизвестная сумма: `переделка воды — ?`.
6. Составная строка: `5 000 + 1 500 обратный клапан` — должна быть разделена на две строки.
7. Материалы одной суммой или с количествами.
8. Корректировки взаиморасчётов: аванс, зарплата помощника, оборудование монтажника, премия.
9. Подытоги по объекту и общий итог отчёта.

Контроль арифметики:

- отчёт 13.07: расчёт совпадает с указанным итогом 291 600 ₽;
- отчёт 10.08: строки дают 325 900 ₽, указан итог 324 900 ₽ — расхождение 1 000 ₽;
- отчёт 11.09: строки Primavera дают 99 520 ₽, указан итог 99 420 ₽ — расхождение 100 ₽;
- отчёт 20.08 содержит четыре строки без суммы, поэтому итог нельзя утвердить.

Точка в записи `15.000` трактуется как разделитель тысяч, а не десятичная часть.

## 3. Каноническая строка факта

Каждая распознанная строка хранится отдельно и неизменно ссылается на источник:

| Поле | Назначение |
|---|---|
| report_id | внутренний номер отчёта |
| source_file_id | исходный файл Telegram |
| source_page / source_text | страница и исходная формулировка |
| installer_id | монтажник/бригада |
| period_from / period_to | отчётный период |
| object_label | название объекта из отчёта |
| deal_id | подтверждённая сделка Мегаплана |
| line_type | work, material, equipment_offset, advance, payroll_offset, bonus, subtotal, unknown |
| normalized_name | нормализованный вид работы/материала |
| quantity / unit / rate | объём, единица и ставка |
| amount | сумма строки до корректировок |
| settlement_sign | +1 начисление, −1 удержание, 0 справочная строка |
| planned_offer_row_id | совпавшая плановая позиция сделки |
| match_status | exact, suggested, confirmed, unplanned, needs_clarification |
| approval_status | draft, installer_confirmed, manager_approved, rejected |
| payment_status | not_due, due, partially_paid, paid |

Итоги и подытоги не превращаются в затраты повторно: это контрольные строки.

## 4. Привязка отчёта к сделкам

Отчёт сначала делится на смысловые блоки по заголовкам объектов. Для каждого блока бот строит кандидатов:

1. точный номер сделки;
2. точное или близкое совпадение адреса;
3. клиент или устойчивый псевдоним объекта (`Примавера`, `Дитейлинг`, `Вестгарден`);
4. исполнитель сделки совпадает с отправителем;
5. активная сделка и близость даты работ;
6. последние пять сделок, где отправитель указан исполнителем.

Автопривязка допустима только при одном однозначном кандидате. Иначе монтажнику показываются кнопки с пятью кандидатами, адресом, клиентом и номером. Блоки одного отчёта могут быть привязаны к разным сделкам.

## 5. Сопоставление с плановыми позициями

Порядок поиска:

1. ранее подтверждённый словарь синонимов для данного вида работ;
2. нормализованное название + единица измерения;
3. категория работы + ключевые параметры;
4. ручной выбор из плановых строк сделки.

Количество закрывается на существующих плановых строках по принципу FIFO. Повторные отчёты накапливают факт, но не могут незаметно закрыть объём сверх плана.

Если совпадения нет, создаётся фактическая строка `Вне плана`. Она видна монтажнику и руководителю, но не добавляется автоматически в продаваемые позиции Мегаплана. Руководитель отдельно решает: принять за счёт организации, перевыставить заказчику, отклонить или перенести в другую сделку.

Изменение единиц (`м²` ↔ `пог. м`, фасонные части ↔ условные единицы) запрещено без подтверждённого коэффициента. Подтверждённое правило сохраняется в справочник только для конкретного вида работ.

Строка `по таблице` раскрывается из самой свежей Excel-вложенной ведомости соответствующей сделки в Мегаплане (допустимые названия: `Монтажная ведомость` и `Расчётная ведомость`). Бот показывает её строки и просит отметить фактически выполненные количества; сумма из PDF остаётся контрольной и не распределяется произвольно.

Для строк материалов действует контекст отчёта: явное название объекта имеет приоритет, иначе материал наследует последний однозначно определённый объект/раздел с уверенностью 95%. Такая привязка показывается пользователю как предположение и подтверждается вместе с отчётом.

## 6. Разделение экономики и взаиморасчётов

`Фактическая себестоимость сделки` включает утверждённые работы и материалы, относящиеся к сделке.

`К оплате монтажнику` считается отдельно:

`утверждённые начисления + премии − авансы − удержания − оборудование монтажника − произведённые выплаты`.

Зарплата помощника, аванс и «кондиционеры мои» не являются отрицательной себестоимостью объекта. Это отдельные операции взаиморасчётов. У каждой операции обязательны тип, дата, основание и подтверждение руководителя.

## 7. Состояния обработки

1. Получен файл.
2. Распознан отчёт и период.
3. Выделены объекты и строки.
4. Уточнены неоднозначные сделки.
5. Уточнены строки с `?`, `по таблице`, неясной единицей или расхождением итогов.
6. Монтажник подтверждает распознанный объём.
7. Руководитель видит протокол изменений и утверждает/корректирует.
8. Факт попадает в экономику, начисления — в ведомость к оплате.
9. Каждая выплата фиксируется отдельной транзакцией; утверждённые строки не переписываются задним числом, корректировки идут новыми строками.

## 8. Макет руководителя

- `Сводка`: план/факт по сделкам, отклонения и суммы к оплате.
- `Отчёты для сверки`: каждый исходный отчёт выделен отдельным блоком по дате; внутри сохранены все строки PDF в исходном порядке, группировка по объектам, расчётные подытоги объектов, исходные итоги и общий контрольный итог. Детальные строки можно сворачивать штатной группировкой Excel.
- `План-факт`: одна строка на плановую позицию сделки, плановый и накопленный фактический объём.
- `Фактические строки`: полный нормализованный журнал из отчётов.
- `Взаиморасчёты`: начисления, авансы, удержания, выплаты и остаток.
- `Требует уточнения`: неизвестные суммы, внешние таблицы, неоднозначные сделки и арифметические расхождения.
- `Справочники`: подтверждённые синонимы и коэффициенты единиц.

## 9. Макет монтажника

- `Мои объекты`: только сделки, где пользователь является исполнителем.
- `Отчёты для сверки`: те же построчные блоки собственных отчётов с датами, исходными формулировками и подытогами, но без управленческих полей и экономики организации.
- `Работы`: весь плановый объём, ранее закрыто, текущий отчёт, накопленный факт, остаток и сумма.
- `Материалы`: заявленные материалы и статус возмещения.
- `Взаиморасчёты`: начислено, удержано, выплачено, остаток к оплате.
- `Требует уточнения`: только вопросы по собственному отчёту.

Монтажник не получает листы с выручкой, прибылью, закупочной стоимостью оборудования и данными других исполнителей.

## 10. Критерии готовности реализации

- один отчёт корректно разбивается минимум на три сделки;
- строки с `?` не попадают в утверждённые суммы;
- агрегат `по таблице` раскрывается из ведомости сделки и требует выбора фактически закрытых строк/количеств;
- материал без названия объекта получает контекст предыдущего блока с явно показанной уверенностью 95%;
- расхождение подытога блокирует утверждение соответствующего блока;
- повторная загрузка того же файла не создаёт дублей;
- факт накапливается по позиции и отчётам;
- плановые данные сделки никогда не затираются фактом;
- монтажник и руководитель получают разные представления одних данных;
- после выплаты сохраняется неизменяемая запись с датой и суммой.
